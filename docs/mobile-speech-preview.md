## 원인과 한계
모바일 continuous=false와 onend 후 120ms 재시작은 과거에도 있었다. 사이트 효과음 호출은 없으며, 시스템 음성인식 시작음이라는 설명이 무음 모드 관찰과 맞는다. 실제 갤럭시 이벤트와 소리를 대조하지 않아 과거와 현재의 차이 원인은 확정하지 못했다.
Chromium은 Android SpeechRecognizer의 startListening을 호출하고 최종 결과 후 세션을 끝낸다. 정상 발화 뒤의 시스템 소리는 이 수정으로 제거하지 못할 수 있다.

## 변경
모바일의 결과 없는 종료 또는 오류 뒤에는 600/1200/2400ms 간격으로 재시도하고, 네 번째 연속 실패에서 기존 오류·재시작 UI로 넘긴다. 텍스트가 들어오면 누적 횟수를 초기화한다.
정상 발화 뒤 120ms 재시작, continuous=false, 기존 결과 덮어쓰기와 조각 결합 규칙은 유지한다. 따라서 continuous=true에 따른 과거 중복 인식 회귀를 피한다.
모바일의 이미 종료한 세션·이미 실행 중인 인식기 재시작도 막는다.
PC 녹음·AI 전사, 질문 음성, 답변 저장, 화면 구성은 수정하지 않는다.
재시작 대기 구간에는 말이 누락될 수 있으므로 정상 발화에 대기시간을 적용하지 않는다. 긴 무음으로 인식이 멈춘 경우 버튼으로 다시 켜야 한다.

## 갤럭시 Chrome에서 확인할 항목
PR의 Vercel Preview 링크만 열고 운영 사이트와 각각 같은 질문으로 비교한다. Chrome/Android/One UI/Google 음성 서비스 버전, 소리 모드, 시간도 기록한다.
1. 소리 모드에서 60초 영어 답변: 실시간 텍스트가 계속 적히는지, 소리가 문장 종료 때인지 무음 때인지 기록한다.
2. 2~3초 쉬고 이어 말하기: 이어지는 문장이 누락·중복 없이 남는지 확인한다.
3. 20~30초 이상 말하지 않기: 무한 반복음이 줄고 인식 종료가 표시되는지, 받아쓰기 다시 켜기로 이어 말할 수 있는지 확인한다.
4. 'I like running'을 한 번 말하고 같은 표현을 의도적으로 한 번 더 말하기: 시스템 중복은 없어야 하며 실제 반복은 보존되어야 한다.
5. 정지·문항 이동·질문 다시 듣기: 이전 인식기가 뒤늦게 다시 켜지지 않고 답변이 보존되는지 확인한다.
6. 다음 문항과 결과 화면: 답변 텍스트 저장이 유지되는지 확인한다.
7. 무음 모드: 질문 음성과 받아쓰기가 계속 동작하는지 확인한다.
8. PC: 녹음 재생과 기존 AI 전사 경로, 질문 음성 및 답변 저장을 확인한다.

자동 테스트는 시스템 알림음 감소를 증명하지 않는다. 실기기 확인 전 병합·운영 배포하지 않는다.
