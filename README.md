# Yumi OPIc

OPIc AL 준비를 위한 개인 연습 앱입니다. 서베이 11개 주제와 돌발 7개 주제를 연습할 수 있습니다.

## 현재 범위

아래 11개 서베이 토픽과 별도의 돌발 문제은행을 제공합니다.

- 혼자 아파트 거주
- 음악 듣기
- 해변
- 공원
- 콘서트
- 쇼핑
- 조깅
- 걷기
- 헬스
- 집에서 보내는 휴가
- 해외여행

활성 문제은행은 `src/data/survey-bank.ts`를 중심으로 구성합니다. 각 주제는 기본 8문항에 롤플레이 3문항을 더해 11문항입니다. 음악 듣기만 기억에 남는 경험과 비교를 하나씩 더 두어 13문항입니다.

- 묘사 2문항
- 습관 1문항
- 경험 2문항
- 기억에 남는 경험 1문항
- 롤플레이 질문하기(11번) 1문항
- 롤플레이 문제 해결(12번) 1문항
- 롤플레이 관련 경험(13번) 1문항
- 비교 1문항
- 이슈 1문항

총 123문항입니다. 같은 유형에 문항이 여럿이면 그 가운데 하나를 무작위로 뽑습니다.

## 화면 구성

홈(`/`)은 **오늘 무엇을 연습할지 고르는 화면**입니다. 배경 설문은 한 번 정하면
브라우저에 남는 설정이라 `/survey` 로 따로 두었습니다.

- 마지막 연습이 있으면 맨 위에 **이어서 연습하기**가 붙습니다. 주제별 연습은 같은
  주제로, 모의고사·랜덤 연습은 같은 모드로 새로 뽑아 다시 시작합니다.
- 아래에 **주제별 연습**·**실전 모의고사**·**1문제 랜덤 연습**·**1토픽 랜덤 연습**과 **최근 기록** 5개가 있고,
  그다음에 지금 고른 배경 설문 상태와 **배경 설문 수정** 링크가 있습니다.
- 저장된 설정이 없는 첫 방문만 `/survey` 로 보냅니다. 실제 시험처럼 Step 1 부터
  시작하되, 두 번째 방문부터는 설문을 다시 지나지 않습니다.

배경 설문(`/survey`)은 실제 오픽 시험의 **Background Survey** 화면을 그대로 옮겨 놓은
것입니다. 문항 8개와 선택지 84개의 문구·순서·선택 방식은
[2026 오픽 서베이 항목](https://baby.tali.kr/opic-survey) 안내를 따르며,
`src/data/survey-form.ts` 한 곳에서 관리합니다.

- 1~3번(직업·학생·수강)은 실제 시험처럼 고를 수 있지만 이 앱은 업무·학업 주제를
  다루지 않아 연습 문제로 이어지지 않습니다. 기본값은 일 경험 없음, 학생 아님,
  수강 후 5년 이상 지남입니다.
- 문제은행이 있는 11개 항목에는 **연습 가능** 표시가 붙고, 처음에는 이 항목이 모두
  켜져 있습니다. 나머지 항목도 실제 시험처럼 고를 수 있으나 고르면 **문제 준비 중**
  으로 표시하고 출제에는 쓰지 않습니다.
- 4~8번에서 고른 항목이 곧 출제 범위입니다. 연습 가능한 항목을 3개 이상 골라야
  주제별 연습과 실전 모의고사를 시작할 수 있고, 실제 시험의 합산 12개 기준은 안내
  문구로만 보여 줍니다.
- 아래 `Next ▶` 는 홈으로 이어집니다. 연습 방식은 홈에서 고릅니다.
- 선택은 `yumi-opic:settings` 의 `surveyChoiceIds` 에 그대로 남고, 그 가운데 문제
  은행이 있는 주제만 추린 값이 `enabledSurveyIds` 입니다. 두 값은 `saveSurveyChoices`
  와 `saveEnabledTopics` 로만 함께 바뀝니다. 이 화면에 들어오면 아무것도 고치지
  않아도 방문 사실이 저장돼, 홈이 다시 설문으로 되돌리지 않습니다.

나머지 화면은 다음과 같습니다.

- 주제별 연습(`/topics`): 서베이 11개·돌발 7개 주제를 분류 버튼으로 전환하는 목록. 주제마다 지금까지 연습한 횟수를 함께
  보여 주고, 목록 아래에 주제별·랜덤 연습 기록이 쌓입니다.
- 실전 모의고사(`/exam?mode=full`): 시작 화면에서 배경 설문 주제를 고릅니다.
  처음에는 11개가 모두 켜져 있습니다. 걷기·콘서트·조깅은 목록에 **모의고사 제외**로
  남고 출제에서만 빠지며, 옆 링크로 따로 연습할 수 있습니다. 나머지 주제는 3개 이상
  남겨야 합니다. 아래에 모의고사 기록을 보여 줍니다.
- 피드백 모아보기(`/report?ids=…`): 연습 기록 목록에서 고른 회차의 질문·답변·AI
  피드백을 한 화면에 모아 보고, 그대로 인쇄해 PDF 로 저장합니다.

연습 기록은 화면마다 그 화면의 모드만 보여 주며, **전체 삭제**도 그 목록에 보이는
기록만 지웁니다. 목록 왼쪽의 체크상자로 여러 회차를 골라 **모아보기 · PDF 저장**
하거나 **선택 삭제**할 수 있습니다. 홈의 최근 기록은 보기 전용이라 삭제와 모아보기는
각 화면의 목록에서 합니다.

### 화면 사이를 오가는 길

연습 화면에서 나갈 때는 늘 홈이 아니라 **그 연습을 고른 목록**으로 되돌아갑니다.
다음 주제를 고르려고 배경 설문을 다시 지나야 했던 것을 없애기 위해서입니다.
`src/lib/nav.ts` 한 곳에서 정합니다.

| 화면 | 나가기 | 다음 |
| --- | --- | --- |
| 주제별 연습·랜덤 연습 | `← 주제별 연습`(`/topics`) | — |
| 실전 모의고사 | `← 실전 모의고사`(시작 화면) | — |
| 연습 결과 | 위와 같음. 오른쪽에 `홈 →` | `다른 주제 연습하기 →` |

답변이나 녹음이 있는 채로 연습 화면을 벗어나려 하면 확인창이 뜹니다. 기록은 결과
화면에 닿아야 처음 저장되기 때문입니다. 새로고침과 창 닫기는 브라우저 기본 확인창이
막지만, **브라우저 뒤로가기 버튼은 막지 않습니다**.

## 연습 방식

### 실전 모의고사

선택한 배경 설문 주제와 돌발 주제를 섞어 실제 시험과 같은 번호 구조로 연습합니다.
주제는 모의고사 시작 화면에서 고르고, 선택값은 `yumi-opic:settings` 에 남습니다.
걷기·콘서트·조깅은 설문에서 골라도 모의고사와 랜덤 연습에는 나오지 않고
(`DRAW_EXCLUDED_TOPIC_IDS`), 주제별 연습에서만 풉니다.

2~15번은 다섯 구간으로 나눕니다.

| 구간 | 번호 | 유형 | 출처 |
| --- | --- | --- | --- |
| 세트 1 | 2·3·4 | 묘사 → 습관 → 경험 | 배경 설문 또는 돌발 |
| 세트 2 | 5·6·7 | 묘사 → 경험 → 기억에 남는 경험 | 배경 설문 또는 돌발 |
| 세트 3 | 8·9·10 | 묘사 → 경험 → 기억에 남는 경험 | 배경 설문 또는 돌발 |
| 롤플레이 세트 | 11·12·13 | 질문하기 → 문제 해결 → 관련 경험 | 배경 설문 |
| 어드밴스 세트 | 14·15 | 비교 → 이슈 | 배경 설문 또는 돌발 |

번호별 유형은 **배경 설문 구간에만** 적용합니다. 돌발은 아래처럼 자료 순서를 따릅니다.

실제 시험처럼 **세 구간은 배경 설문에서, 두 구간은 돌발에서** 뽑습니다
(`FULL_EXAM_SURPRISE_GROUPS`). 돌발이 어느 구간에 들어갈지는 회차마다 무작위로
정하며, 롤플레이 구간만 예외로 늘 배경 설문에서 나옵니다. 돌발 문제은행에
`roleplay_*` 문항이 없기 때문입니다. 한 회차에 같은 주제가 두 구간에 나오지 않으며,
세트를 완성할 수 없는 배정이 나오면 다른 구간 조합으로 다시 배정합니다.
그래서 배경 설문 주제는 최소 3개를 골라야 합니다(`MIN_FULL_EXAM_SURVEY_TOPICS`).

돌발은 주제마다 가진 유형이 제각각이라 번호별 유형을 강요하지 않습니다. 없는 유형을 지어내
연습량만 늘리는 대신 **제공 자료 안에서만** 세트를 만듭니다.

- **일반 구간**(2~4·5~7·8~10번)은 자료의 **1번을 고정**하고, 나머지 두 문항을 자료 순서를
  지켜 무작위로 고릅니다. 1·2·3 뿐 아니라 1·2·4, 1·3·4도 나옵니다. 비교·이슈는 어드밴스
  구간 몫이라 여기서 뺍니다. 앞 질문을 전제로 하는 산업 문항은 그 앞 질문 뒤에만 나옵니다.
- **어드밴스 구간**(14~15번)만 비교 → 이슈 순서를 지킵니다. 두 유형을 모두 가진 네 주제
  (재활용, 산업, 구직·진로, 직업·직장)만 이 구간에 들어갑니다.

화면과 결과에는 자료 번호가 아니라 시험 번호를 적습니다.

11~13번은 하나의 주제에서 이어지는 세트로 생성합니다. 11번에서 정보를 묻고, 12번에서 관련 문제를 해결하며, 13번에서는 이어지는 경험을 `배경 → 문제 → 해결·행동 → 결과` 구조로 말하는 연습을 합니다.

번호와 유형의 대응은 자주 나오는 순서를 정리한 것이며, 실제 시험에서 항상 같은 번호에 고정된다는 뜻은 아닙니다.

### 주제별 연습

돌발 주제는 `src/data/surprise-bank.ts`에 있으며, 제공 자료의 영어 지문·제목·번호·순서를 보존합니다. 한국어 해석도 함께 제공합니다.
돌발은 문항을 새로 지어내지 않고 제공 자료 35문항만 씁니다. 그래서 주제마다 가진 유형이 다르며, 모의고사도 그 범위 안에서 세트를 만듭니다.

| 돌발 주제 | 문항 수 | 모의고사 일반 구간에서 나올 수 있는 조합 |
| --- | ---: | --- |
| 재활용 | 7 (1~4, 5-A, 5-B, 6) | 1·2·3 / 1·2·4 / 1·3·4 |
| 산업 | 5 | 1·2·3 |
| 구직·진로 | 5 | 1·2·3 |
| 직업·직장 | 6 | 1·2·4 |
| 병원·치과 | 4 | 1·2·3 / 1·2·4 / 1·3·4 |
| 약속·예약 | 4 | 1·2·3 / 1·2·4 / 1·3·4 |
| 미용실 | 4 | 1·2·3 / 1·2·4 / 1·3·4 |

14~15번 어드밴스 구간은 비교와 이슈를 모두 가진 재활용·산업·구직·진로·직업·직장만 채웁니다.

돌발 연습은 35문항을 주제별로 원래 순서대로 출제합니다. 문항 선택·결과·피드백 리포트에는 원래 번호를 표시하고, 내부의 고유 숫자 슬롯으로 답변을 저장해 5-A/5-B가 덮어쓰이지 않습니다. 산업의 연결 질문은 같은 주제 안에서 앞 질문 다음에 나옵니다. 출처는 **제공 자료**로 표시합니다. 실전 모의고사에서는 다섯 구간 중 두 구간을 돌발 세트가 채웁니다.

서베이 주제를 하나 고르면 **자기소개 없이 2~15번**을 구성합니다. 2·5·8번은 묘사, 3번은 습관, 4·6·9번은 경험, 7·10번은 기억에 남는 경험, 11~13번은 롤플레이 질문하기·문제 해결·관련 경험, 14번은 비교, 15번은 이슈입니다. 2~15번은 모두 선택한 한 주제에서 고릅니다. 각 번호의 유형에 맞춰 무작위로 뽑으므로 같은 질문이 중복될 수 있으며, 답변은 번호별로 따로 저장됩니다. 기출 복원 문항을 우선하고 없는 유형은 출제 유형 기반 문항으로 채웁니다. 결과의 **문제 다시 뽑기**로 새로 배정할 수 있습니다.

질문은 음성으로 듣고, 지문·해석은 연습 도구의 해당 버튼을 누르는 동안에만 확인합니다. **이전·다음** 또는 **문항 번호**로 이동해 원하는 문제만 답변할 수 있습니다. **연습 마치고 결과 보기**를 누르면 마지막 문항까지 넘기지 않고도 결과를 저장합니다. 문항을 이동해도 작성한 답변은 유지됩니다.

답변 텍스트가 비어 있거나 공백뿐인 문항은 AI 피드백 버튼을 비활성화하고, 단어 수·평균 단어 수·답변 시간 등 통계에서 제외합니다. 평균 단어 수는 답변한 문항 수로만 나누며, 모든 문항을 건너뛰면 평균은 `—`로 표시합니다. 녹음 파일만 있고 받아쓰기 텍스트가 없는 문항도 동일하게 처리합니다.

### 랜덤 연습

무작위로 뽑는 연습은 **단위 2가지 × 범위 3가지**, 모두 여섯 가지입니다.

| 범위 \ 단위 | 1문제 (`mode=single`) | 1토픽 (`mode=set`) |
| --- | --- | --- |
| 서베이+돌발 | `/exam?mode=single` | `/exam?mode=set` |
| 서베이 | `/exam?mode=single&scope=survey` | `/exam?mode=set&scope=survey` |
| 돌발 | `/exam?mode=single&scope=surprise` | `/exam?mode=set&scope=surprise` |

- **1문제**: 서베이 기출 복원 문항과 제공된 돌발 문항 가운데 하나를 뽑습니다. 앞 질문의
  답을 전제로 하는 돌발 문항은 단독 추첨에서 제외합니다.
- **1토픽**: 주제 하나를 고른 뒤 그 주제에서 가능한 세트 유형을 같은 확률로 뽑습니다.
  2~4번형은 `묘사 → 루틴 → 경험`, 5~7·8~10번형은
  `묘사 → 과거·최초 경험 → 기억에 남는 경험`, 11~13번형은
  `롤플레이 질문하기 → 문제 해결 → 관련 경험`, 14~15번형은 `변화·비교 → 이슈`입니다.
  일반·롤플레이는 3문항, 변화·이슈는 2문항이며 뽑힌 세트 유형은 연습 화면의
  시험 화면 바깥 상단의 **토픽·유형**에 마우스를 올리거나 누르는 동안 확인할 수 있습니다.
  연결 질문은 반드시 같은 세트의 선행 질문 뒤에 나오고, 연결 가능한 세트 중 기출 복원
  문항을 우선합니다. 돌발도 보유 문항으로 가능한 유형을 구성하고, 일반 유형의 문항이
  부족한 돌발 주제는 기존 자료 순서의 연결 세트를 사용합니다. 문항 번호는 자료 번호가
  아니라 연습 순서인 1~3번(변화·이슈는 1~2번)으로 적습니다.

홈의 **랜덤 연습** 표에서 여섯 가지를 모두 고를 수 있고, 주제별 연습 화면에는 전체 범위
링크(오른쪽 위)와 지금 보는 분류의 범위 링크가 있습니다. 뽑은 범위는 시험의
`randomScope` 에 남아서, 결과 화면의 **문제 다시 뽑기**와 홈의 **이어서 연습하기**는 같은
범위에서 새로 뽑습니다. 기록 라벨은 `1토픽 랜덤 연습 (돌발) · 미용실` 처럼 범위와 뽑힌
주제를 적고, 주제별 연습 횟수에는 세지 않습니다. 걷기·콘서트·조깅은 모의고사와 마찬가지로
어느 범위에도 나오지 않습니다(`RANDOM_SCOPE_TOPICS`).

## 응시 화면

연습 화면은 실제 오픽 응시 화면을 그대로 따라 만들었습니다. 화면에 익숙해지는
것도 연습의 일부이기 때문입니다. 실전 모의고사·주제별 연습·랜덤 연습 모두 같은
화면을 씁니다. 주제별 연습에서는 문항 이동 버튼을 추가로 표시합니다. 질문 지문과 해석은 기본적으로 숨깁니다.

토픽·질문 유형·랜덤 세트 구성도 기본적으로 숨깁니다. 시험 영역 바깥 상단 오른쪽의
**토픽·유형**에 마우스를 올리면 작은 팝업으로 나타나고, 떼면 다시 숨겨집니다.
모바일은 누르는 동안, 키보드는 버튼에 포커스를
둔 동안 확인할 수 있습니다. Escape 또는 문항 이동 시 다시 숨기며, 연습 결과와 기록에는
토픽 이름을 표시합니다.

| 실제 시험 | 이 앱 |
| --- | --- |
| `Question n of m` 머리말 | 같음 |
| 왼쪽 면접관(Ava) 화면 | 같음. 질문이 나오는 동안 오른쪽 아래에 소리 표시가 움직입니다 |
| 주황색 ▶ 버튼과 재생 막대 | 같음. 막대는 낭독이 진행되는 만큼 찹니다 |
| `Click 'PLAY' button to Listen` 파란 띠 | 같음. 단계에 따라 문구가 바뀝니다 |
| 세로 마이크 입력 레벨과 마이크 표시 | 현재 입력을 원 하나로 표시합니다. 원은 같은 축에서 위아래로만 움직입니다. 휴대폰처럼 마이크를 한 곳에서만 쓸 수 있는 기기에서는 입력을 잴 수 없어 원이 천천히 오르내리기만 합니다 |
| `문항 진행:` 번호판 | 같음. 지나온 문항은 빗금, 지금 문항은 검은 칸입니다 |
| 파란 안내 문구 | 같음. 실제 시험처럼 **1번 문항에서만** 나옵니다 |
| 주황색 `Next ›` | 같음. 앞 문항으로 돌아갈 때는 번호판을 누릅니다 |

기본 화면에는 이것 말고 아무것도 없습니다. 답변 기록도, 힌트 버튼도 처음에는
보이지 않습니다. 화면 왼쪽 아래 `연습 도구 ▾` 를 눌러야 펼쳐지고, 시험을 새로
시작하면 다시 접힙니다. 실전에 없는 것이 눈에 먼저 들어오면 연습이 아니게 되기
때문입니다.

### 어느 기기에서 연습할까

**노트북(크롬·엣지)을 권합니다.** 기기에 따라 연습의 질이 갈리는데, 갈리는 지점이
받아쓰기 하나가 아니라 그 뒤에 붙는 것 전부이기 때문입니다.

| | 노트북 (크롬·엣지) | 휴대폰·태블릿 |
| --- | --- | --- |
| 브라우저 받아쓰기 | ○ | ○ |
| 녹음본 저장·재생·mp3 내려받기 | ○ | ✕ |
| OpenAI 재전사로 답변 텍스트 교정 | ○ | ✕ |
| 발음 점검 근거 | 두 인식 결과 비교 | `browser_only` |
| AI 피드백 | ○ | ○ (브라우저 받아쓰기만 근거) |

휴대폰은 마이크를 한 번에 한 곳에서만 쓰고 나중에 연 쪽이 가져갑니다. 답변이 빈
채로 남는 것보다는 낫기 때문에 받아쓰기를 살리고 녹음을 접습니다(`src/lib/micShare.ts`).
그 결과 휴대폰에서는 **받아쓰기 텍스트 하나에 모든 것이 걸립니다.** 브라우저
받아쓰기는 발음이 조금만 흐려도 다른 단어를 적는데(`gym` → `dreams`), 녹음본이
없으면 그것을 바로잡을 방법이 없고 AI 피드백도 그 문장을 그대로 믿습니다. 돈은
같이 나가는데 근거만 약해지는 셈입니다.

그래서 안내를 세 곳에 둡니다. **홈 화면**은 휴대폰으로 들어오면 노트북을 권하는
문단을 보여 주고, **응시 화면**은 받아쓰기만 켜졌음을 알리며 잘못 적힌 곳은 `직접
입력·고쳐 쓰기` 로 다듬으라고 알립니다. **결과 화면**은 녹음본 자리와 AI 피드백
버튼 옆에서 무엇을 근거로 분석하는지 밝힙니다. 휴대폰으로 연습하지 말라는 뜻은
아니고, 무엇이 약해지는지 알고 쓰자는 뜻입니다.

### 질문 듣기 규칙

실제 시험 규칙을 그대로 지킵니다.

- 문항마다 **▶ 를 눌러야** 질문이 나옵니다. 자동으로 재생하지 않습니다.
- 질문이 끝난 뒤 **5초 안에** 같은 버튼을 누르면 한 번 더 들을 수 있습니다.
- **재청취는 문항당 한 번**뿐입니다. 창이 닫히거나 한 번 쓰면 버튼이 잠깁니다.
- 남은 시간은 파란 띠에 `다시 듣기 3초` 처럼 보여 줍니다. 실제 시험에는 없는
  표시지만, 5초가 얼마나 짧은지 몸에 익히라고 넣었습니다.
- 답변 시간은 **질문 음성이 끝난 시점부터 0:00 으로** 잽니다. 다시 듣기를 했거나
  이미 답한 문항에 돌아와 다시 들을 때도 같습니다. 질문이 나오는 동안에는 0:00 에
  머뭅니다.

### 질문 낭독 음성

브라우저 내장 낭독(Web Speech API)은 기기마다 목소리가 다르고 기계음이 많이
납니다. 그래서 문제 지문 124개를 **미리 mp3 로 만들어 `public/audio` 에 넣어
두고** 그 파일을 재생합니다. 문제은행이 고정돼 있어 가능한 방식입니다.

- 기기가 달라도 항상 같은 목소리로 들립니다
- 재생할 때마다 드는 비용이 없고, 지연도 없습니다
- 진행 막대를 어림값이 아니라 파일의 실제 길이로 그립니다

파일이 아직 없는 문항은 지금까지처럼 브라우저 낭독으로 읽습니다. 그래서 mp3 를
한 개도 만들지 않아도 앱은 그대로 돌아갑니다.

만드는 방법은 아래와 같습니다. 만들어진 mp3 와 `src/data/audio-manifest.json` 은
함께 커밋해야 배포본에 실립니다.

```bash
npm run tts -- --dry-run          # 무엇을 만들지, 얼마나 드는지만 확인
npm run tts                     # 로컬 .env의 OPENAI_API_KEY로 새 문항·바뀐 문항 생성
npm run tts -- --category=surprise # 돌발 주제만 생성 (기존 서베이 음성 보존)
npm run tts -- --topic=recycling  # 재활용 주제만 생성
```

`OPENAI_API_KEY=...`를 프로젝트 루트의 `.env`에 저장하면 Next.js와 TTS 스크립트에서 읽습니다. `.env`는 Git에서 제외하며 키를 클라이언트 코드에 넣지 않습니다.

지문이 바뀌면 그 문항의 해시가 달라져 다음 실행 때 그 문항만 다시 만듭니다.
목소리나 말투는 `OPENAI_TTS_VOICE`, `OPENAI_TTS_INSTRUCTIONS` 로 바꿉니다. 바꾸면
해시가 전부 달라지므로 124개를 다시 만듭니다(대략 $0.3).

### 연습 도구

`연습 도구 ▾` 를 펼치면 답변 기록과 힌트 버튼이 나옵니다. 실전에 없는 것들이라
한 겹 뒤에 두었습니다.

실전에는 문제 지문이 화면에 없습니다. 그래서 펼친 뒤에도 지문은 여전히 보이지
않고, 버튼을 **누르고 있는 동안에만** 나타납니다. 손을 떼면 바로 사라집니다.

- `지문 보기 (꾹)` — 영어 원문과 유형·주제·출처
- `해석 보기 (꾹)` — 한국어 해석
- `키워드 보기 (꾹)` — 해당 문항에 키워드가 있을 때만

누른 횟수는 문항별로 세어 결과 화면에 보여 줍니다. 실전에는 없는 도움이니 이
숫자가 0에 가까울수록 실제 시험에 가까운 연습입니다.

힌트 버튼 아래에는 **저장한 표현 · 피드백** 이 붙습니다. 결과 화면에서 별표로
저장해 둔 AI 조언 중 **지금 문항**의 것과 **같은 주제의 다른 문항**의 것을 나눠
보여 줍니다. 지난번에 지적받은 표현을 다시 말해 보라고 꺼내 두는 자리입니다.
기본은 접혀 있고, 힌트와 달리 펼친 횟수는 세지 않습니다. 목록에서 바로
`지우기` 로 저장을 풀 수 있습니다.

### 답변 입력

기본은 마이크입니다. 질문 낭독이 끝나면 녹음이 저절로 시작됩니다. 녹음 중인지는
실제 화면과 같은 자리, 입력 레벨 표시 아래 마이크가 빨갛게 깜빡여 알려 줍니다.

노트북은 받아쓰기와 녹음이 마이크를 함께 씁니다. 휴대폰은 마이크를 한 번에 한
곳에서만 쓰기 때문에 받아쓰기만 켜고 녹음본 저장은 접습니다. 아래
[휴대폰에서 아무것도 받아쓰지 못하던 문제](#휴대폰에서-아무것도-받아쓰지-못하던-문제)
를 참고하세요.

받아쓴 내용을 보려면 `연습 도구` 를 펼칩니다. 말하는 대로 실시간으로 적히고, 아직
확정되지 않은 부분은 흐리게 보여 어디까지 인식됐는지 확인할 수 있습니다.

마이크를 못 쓰는 브라우저이거나 받아쓴 결과를 고치고 싶으면 `직접 입력·고쳐 쓰기`
로 바꿔 키보드로 씁니다.

### 결과 화면

연습을 마치면 요약 통계 아래에 문항별 답변을 다시 볼 수 있는 목록이 나옵니다.
답변하지 않고 넘긴 문항이 있으면 목록 위에 **답변한 문항 / 전체** 버튼이 생기고,
기본은 **답변한 문항**입니다. 실제로 말한 답변만 남으니 15문항 중 몇 개만 푼
연습에서도 바로 확인할 수 있습니다. 넘긴 문항의 질문을 보고 싶으면 **전체**를
누릅니다. 한 문항도 답변하지 않았다면 목록이 비지 않도록 처음부터 전체를 보여
줍니다.

### AI 피드백과 연습 기록

- 받아쓰기는 브라우저 내장 Web Speech API를 사용합니다. 브라우저에 따라 음성 인식에 네트워크 연결이 필요하며, 지원하지 않는 환경에서는 직접 입력할 수 있습니다.
- 휴대폰에서는 녹음본이 남지 않습니다. AI 피드백 버튼 자체는 답변 텍스트만 있으면 열리지만, **그 텍스트가 브라우저 받아쓰기 그대로라는 것이 중요합니다.** 녹음본이 없으면 OpenAI 재전사로 바로잡는 단계가 통째로 빠져(발음 점검 근거도 `browser_only` 로 내려갑니다) 받아쓰기가 잘못 적은 문장을 고쳐 주는 조언이 나옵니다. 그래서 결과 화면은 녹음본 자리와 피드백 버튼 옆 두 곳에서 무엇을 근거로 분석하는지 밝히고, 홈 화면은 휴대폰으로 들어왔을 때 노트북을 권합니다. 자세한 기준은 [어느 기기에서 연습할까](#어느-기기에서-연습할까)를 보세요.
- 결과 화면에서 AI 피드백을 요청한 문항만 질문·답변 텍스트·답변 시간과 녹음본을 서버로 보냅니다. 녹음본이 있으면 OpenAI로 한 번 더 전사해 브라우저 받아쓰기와 비교합니다. 두 인식 결과의 차이는 발음 점검의 참고 신호이며, 확정적인 발음 판정은 아닙니다.
- **AI 피드백 한 번에 받기**: 여러 문항을 푼 뒤 결과 요약 바로 아래 버튼 하나로 답변한 문항 전체의 피드백을 받습니다. 문항마다 개별 버튼과 똑같은 요청(`/api/feedback`)을 3개씩 동시에 보내고, 끝나는 대로 그 문항 카드에 붙습니다. 접힌 문항 머리에는 `분석 중… / ✓ 피드백 / 분석 실패` 가 떠서 펼치지 않아도 진행을 볼 수 있습니다. **이미 피드백이 있는 문항과 지금 분석 중인 문항은 보내지 않으므로**, 다시 누르면 받지 못한 문항만 요청합니다. 도중에 **멈추기**를 누르면 이미 보낸 문항만 마저 받고, 서버에 키가 없을 때(503)처럼 남은 문항도 똑같이 실패할 오류가 나면 스스로 멈춥니다. 어느 문항을 보낼지는 `src/lib/feedbackBatch.ts` 의 `slotsAwaitingFeedback` 한 곳에서 정합니다.
- 문항 카드의 개별 **AI 피드백 받기**도 그대로 있습니다. 이미 피드백을 받은 문항의 **다시 분석**만 지금 피드백이 새 결과로 바뀐다는 것을 한 번 묻습니다.
- 피드백은 **총평과 흐름 점검**(두괄식 도입 → 활동·디테일 → 감정·의미) → **고칠 점**(번호·유형·핵심 한 줄·설명·`이렇게 말해 보세요` 예시) → **Before / After** 순서로 보여 줍니다. 스토리 흐름에 해당하는 유형은 강조색으로, 전달·발음·문법은 차분한 색으로 칠해 코칭 우선순위를 색으로도 드러냅니다. 결과 화면과 피드백 모아보기가 같은 컴포넌트(`src/components/FeedbackDetails.tsx`)를 씁니다.
- **Before / After**: 피드백과 함께 **내가 실제로 말한 답변을 소리 내어 읽을 만하게 고친 답변**(`improvedAnswer`)을 받아 보여 줍니다. 고칠 점이 요구한 수정은 그 자리에 모두 반영하고, 그 밖에도 어색한 표현·문장 구조·연결을 다듬어 자연스러운 구어체가 되게 합니다. 읽고 따라 말할 문장이라 어색한 문장을 그대로 두는 쪽이 더 나쁩니다. 대신 사용자의 단어·예시·생각과 이야기 순서는 그대로 두고, 말하지 않은 내용을 더하거나 말한 내용을 빼지 않으며, 답변의 수준과 길이(10% 안팎)도 지키도록 프롬프트에서 지시합니다. 바뀐 곳은 단어 단위로 맞댑니다(`src/lib/answerDiff.ts`). 말하기 연습이라 대소문자와 문장부호만 다른 곳은 칠하지 않습니다.
- **읽을 문장이 먼저입니다.** 소리 내어 읽을 것은 After 라서 After 를 위에 두고 **Before 는 접어 둡니다.** Before 의 빨간 취소선이 화면에서 가장 무거워, 위에 두면 고친 답변보다 먼저 눈에 들어오기 때문입니다. 피드백 모아보기(`/report`)와 그 인쇄본은 넘겨 볼 화면이 아니라 남겨 두는 기록이라 Before 를 펼친 채로 그립니다.
- **바뀐 곳의 두 등급**: 고칠 점마다 자기가 고친 답변에서 손댄 자리를 그대로 인용해 함께 돌려받습니다(응답의 `itemQuotes` → 항목의 `afterQuote`). 인용문은 고친 답변을 쓴 뒤에 그 텍스트에서 떠 와야 하므로 스키마에서 `improvedAnswer` 뒤에 둡니다. 그 인용문을 After 안에서 되찾아 바뀐 곳을 **고칠 점이 요구한 곳**(`item`)과 **자연스러움만 손본 곳**(`fluency`)으로 가릅니다. 같은 말이 여러 번 나오면 바뀐 단어를 품은 자리를 고르고, 한 곳에 여러 항목이 걸리면 앞선(더 중요한) 항목이 이깁니다. 인용문을 못 찾으면 조용히 `fluency` 로 남습니다. 덜 칠하는 쪽이라 틀려도 화면이 망가지지 않습니다. 인용문이 없는 예전 피드백은 바뀐 곳을 모두 `item` 으로 봅니다.
- **색은 진한 등급에만 씁니다.** 고칠 점이 손댄 자리는 Before 에 빨간 취소선, After 에 초록으로 칠하고 그 항목 번호를 위 첨자로 답니다. 번호는 위 `고칠 점` 목록과 같은 번호이고, 한쪽에 손을 올리면 다른 쪽이 함께 밝아집니다. **자연스러움만 손본 곳은 기본으로 칠하지 않습니다.** 한 답변에서 열 곳을 넘기기도 해서 옅게라도 칠하면 답변이 다시 얼룩져 "다 틀렸다"로 읽힙니다. `다듬은 곳 N군데 보기` 를 누를 때만 점선 밑줄로 보여 주고, 모아보기·인쇄본에는 기록이므로 처음부터 그립니다.
- **따라 읽기**: After 를 눈으로 훑고 넘어가지 않도록, `따라 읽기` 를 누르면 낱말 하나씩 정해진 속도로 표시가 흘러갑니다. 그 속도에 맞춰 소리 내어 읽는 것이 이 화면의 목적입니다. 멈추면 읽던 자리에 표시가 남고, 다 읽으면 표시를 거둡니다. 속도는 분당 낱말 수로 60~180 사이에서 사용자가 정하며(`src/lib/readAloud.ts`), 고른 값은 브라우저에 남아 다음 문항에서 다시 고르지 않아도 됩니다. 표시는 배경과 글자색만 바꿉니다. 여백을 주면 표시가 옮겨 갈 때마다 글자가 밀려 읽던 자리를 잃습니다. 화면 밖으로 나간 낱말은 끌어옵니다. 모아보기·인쇄본에는 재생기를 그리지 않습니다.
- **읽은 횟수와 마이크 확인**: 끝까지 따라 읽으면 한 번으로 세어 그 회차 기록에 남깁니다(`SavedResult.readCounts`). 지난 기록을 열어 읽어도 같은 회차에 쌓입니다. `마이크로 확인`을 켜면 읽는 동안 브라우저 받아쓰기가 함께 돌아, 읽을 글을 얼마나 따라왔는지 낱말 단위로 재어(순서를 지킨 채 겹치는 낱말 수 ÷ 읽을 글의 낱말 수) 70% 아래면 또렷하게 읽어 보라고 한 줄만 알립니다. **통과 조건이 아닙니다.** 브라우저 받아쓰기는 제대로 읽어도 곧잘 틀리므로(그래서 이 앱에 녹음본 재전사가 있습니다) 커버리지와 상관없이 횟수는 그대로 셉니다. 받아쓰기를 못 쓰는 브라우저에서는 이 버튼이 아예 나오지 않습니다.
- **한 항목이 여러 조각으로 갈리면 이어 붙입니다.** 긴 문장을 고치면 그 안의 몇 단어가 예전 답변과 우연히 맞아 조각이 갈립니다. 사이에 낀 것이 바뀌지 않은 말뿐일 때만 이어 한 덩어리로 칠하고, 번호도 한 번만 답니다. Before 에는 이어 붙이지 않습니다. 저쪽은 무엇을 뺐는지 보는 곳이라 빼지 않은 말에 취소선을 그으면 거짓말이 됩니다.
- 비교의 바탕 답변(녹음본이 있으면 OpenAI 전사, 없으면 브라우저 받아쓰기)은 `improvedFrom` 으로 함께 저장합니다. 나중에 브라우저 받아쓰기로 되돌려도 비교가 흔들리지 않습니다. 이 기능 전에 받은 피드백에는 비교가 없고, **다시 분석**하면 생깁니다.
- **OpenAI 전사는 버리지 않고 답변 텍스트로 씁니다.** 브라우저 받아쓰기는 발음이 조금만 흐려도 엉뚱한 단어를 적는데(`gym` → `dreams`), 돈을 들여 받은 전사가 대체로 더 정확합니다. 그래서 프롬프트에만 쓰고 버리지 않고 화면으로 돌려받아, 그 문항의 답변과 단어 수·문장 수 통계를 다시 받아쓴 텍스트로 바꿔 저장합니다. 답변 상자에 **OpenAI 받아쓰기** 표시가 붙고, 그 자리에서 원래 브라우저 받아쓰기를 펼쳐 보거나 되돌릴 수 있습니다. 전사가 비어 있거나 대소문자·문장부호만 다르면 바꾸지 않습니다.
- 원본 브라우저 받아쓰기는 `browserAnswers`로 함께 저장합니다. **다시 분석**할 때는 이 원본을 보내 두 인식 결과를 견주므로, 여러 번 분석해도 발음 점검 근거가 사라지지 않습니다. 되돌리면 원본 키까지 지워 예전 기록과 같은 모양으로 남습니다.
- 코칭 기준은 문법 정확성보다 **핵심 주제 → 활동·예시·디테일 → 감정·의미** 흐름과 전달력입니다. 여기에 **두괄식**을 더해, 답변 **첫 몇 문장(3문장 안팎)** 안에 질문에 대한 답이 나왔는지를 `핵심 주제` 판정의 조건으로 봅니다. 꼭 첫 문장일 필요는 없고, 질문을 되받는 식의 자연스러운 도입은 괜찮습니다. 핵심이 분명히 늦을 때만 보강으로 표시하고, 앞쪽에서 말할 짧은 영어 문장을 예시로 줍니다.
- **연결 표현**(`transition`): 생각과 생각 사이(요점 꺼내기, 덧붙이기, 이유·결과, 반응, 마무리)가 뚝 끊기거나 같은 접속사만 되풀이되면, 그 자리에 맞는 연결 표현을 내 문장에 붙인 예시로 줍니다. 표현을 목록으로 정해 두지 않고 맥락에 맞게 AI 가 고릅니다. 스토리텔링과 같은 흐름 유형으로 칩니다. 유형 목록은 `src/lib/feedback.ts` 의 `FEEDBACK_CATEGORIES` 한 곳에 있습니다.
- 다만 **롤플레이 11~13번은 두괄식을 요구하지 않습니다.** 전화 대화에 가까워 인사·상황부터 꺼내는 편이 자연스러워, 요청이나 문제가 충분히 일찍 드러나는지만 봅니다. 어떤 유형을 빼는지는 `src/lib/feedback.ts` 의 `FREE_OPENING_TYPES` 한 곳에 있습니다.
- 기본 피드백 모델은 `gpt-5.6-terra`입니다. 서버에 `OPENAI_API_KEY`를 설정하면 사용할 수 있습니다. `OPENAI_FEEDBACK_MODEL`과 `OPENAI_TRANSCRIBE_MODEL`로 모델을 바꿀 수 있습니다. `.env.example`을 참고하세요.
- AI 피드백 버튼과 결과 화면에는 **비용·토큰 안내를 보여 주지 않습니다.** 운영 참고용 추정치만 `src/lib/cost.ts` 에 남겨 두었습니다. 출력 토큰을 상한까지 쓴다고 보고 계산한 최대치라 실제 청구액은 보통 이보다 적습니다. 단가와 환율은 `RATES` 한 곳에 있으니 값이 바뀌면 여기만 고치면 됩니다. 2026-09 기준 gpt-5.6-terra 입력 $2·출력 $12(100만 토큰), gpt-transcribe 분당 $0.0045, 환율 1,400원으로 잡았습니다. 고친 답변까지 받으면서 출력 상한을 답변 길이에 맞춰 늘렸고(`src/lib/feedback.ts` 의 `feedbackOutputTokenLimit`, route.ts 와 cost.ts 가 함께 씀) 한 문항당 최대 35~60원 정도가 나옵니다. 연결 표현 10기능 목록을 지시문에 넣으면서 문항당 1~2원가량 올랐고, 자연스럽게 고치는 규칙과 인용문(`itemQuotes`)이 붙으면서 지시문 추정치를 1,500 → 1,800 토큰, 출력 상한의 고정분을 1,400 → 1,550 토큰으로 올려 문항당 3원가량 더 붙었습니다.
- 연습 완료 시 질문·답변·답변 시간·힌트/재청취 횟수를 저장하고, AI 피드백이 도착하면 같은 기록에 추가합니다. 주제별 연습·실전 모의고사 화면 아래의 **연습 기록**을 클릭하면 다시 볼 수 있으며, 조회만으로 AI를 다시 호출하지 않습니다.
- 기록 목록의 시각은 **답변이나 AI 피드백을 마지막으로 저장한 때**(`updatedAt`)이며, 날짜뿐 아니라 `2026. 9. 8. 14:32`처럼 분까지 적습니다. 같은 날 여러 번 연습해도 회차를 구분할 수 있고, 나중에 AI 분석을 돌린 회차는 그 시각으로 바뀝니다. 목록 순서는 저장된 회차 순서 그대로입니다. 연습을 마친 시각(`finishedAt`)은 그대로 두고, 결과 화면 머리글에 `저장 · 연습 …`으로 함께 보여 줍니다. 열어 보기만 할 때는 저장하지 않으므로 시각도 움직이지 않습니다. 시각 표기는 `src/lib/history.ts` 의 `formatHistoryStamp` 한 곳에 있습니다.
- 피드백 항목과 총평 옆의 **☆ 저장**을 누르면 그 조언을 문항에 붙여 둡니다. 회차가 아니라 문항에 붙기 때문에, 같은 문항이나 같은 주제를 다시 풀 때 응시 화면의 `연습 도구 ▾ → 저장한 표현 · 피드백`에 그대로 나옵니다. 같은 버튼을 다시 누르면 저장이 풀립니다. `localStorage`의 `yumi-opic:expressions`에 최근 200개까지 남습니다.
- 연습 기록 목록에서 회차를 여러 개 골라 **모아보기 · PDF 저장**을 누르면 `/report` 에서 고른 회차의 질문·답변·피드백을 한 화면에 모아 봅니다. **PDF로 저장 (인쇄)** 버튼은 브라우저 인쇄 창을 열 뿐이라 별도 라이브러리를 쓰지 않으며, 인쇄 대상을 `PDF로 저장`으로 고르면 파일로 남습니다. 인쇄본에서는 버튼과 링크가 빠지고, 다크 테마로 보고 있어도 밝은 배경으로 나갑니다. 담을 범위는 **피드백 받은 문항 / 답변한 문항**으로 바꿀 수 있고, 녹음본은 브라우저에 저장하지 않으므로 담기지 않습니다.
- 여러 회차를 고른 뒤 **선택 삭제**를 누르면 한 번에 지웁니다. 저장은 한 번만 하므로 중간에 실패해 반쯤 지워진 상태가 남지 않습니다.
- `localStorage`의 `yumi-opic:history`에 최근 20회를 저장합니다. 같은 문제를 다시 풀어도 별도 회차로 남습니다. **삭제** 또는 **전체 삭제**로 답변과 피드백을 함께 지울 수 있습니다.
- 기록은 현재 브라우저에만 남습니다. 브라우저 데이터를 지우면 함께 삭제됩니다. 이전 버전의 요약 기록에는 상세 답변이 없어 복원할 수 없습니다.
- 녹음본은 결과 화면에서 재생하거나 **mp3 로 내려받을 수 있습니다.** 브라우저 녹음 원본은 webm/opus 라 휴대폰이나 기본 음악 앱에서는 열리지 않는 일이 잦습니다. 그래서 **녹음본 mp3 다운로드**를 누르면 그 자리에서 브라우저가 한 채널 96kbps mp3 로 다시 만듭니다. 변환은 브라우저 안에서만 일어나 녹음이 서버로 나가지 않고, 인코더(`@breezystack/lamejs`)는 버튼을 누른 뒤에야 불러오므로 평소 화면 무게는 그대로입니다. 90초 답변이면 몇 초가 걸리므로 버튼에 진행률을 적고, 한 번 바꾼 파일은 들고 있다가 다시 누르면 곧바로 내려받습니다. 브라우저가 원본을 읽지 못해 변환이 실패하면 원본(webm) 내려받기 링크를 대신 보여 줍니다. 변환 코드는 `src/lib/mp3.ts` 한 곳에 있습니다.
- AI 피드백으로 보내는 녹음본은 변환하지 않은 원본 그대로입니다. 전사 쪽은 webm 을 그대로 받고, mp3 로 바꾸면 소리만 한 번 더 상합니다.
- 음성 파일은 localStorage에 저장하지 않습니다.

## 받아쓰기가 같은 말을 반복하던 문제

휴대폰 브라우저에서 같은 단어·문장이 계속 쌓이던 문제를 고쳤습니다.

**원인은 `continuous` 설정이었습니다.** 안드로이드 크롬은 `continuous` 를 켜면 인식
중인 가설이 올 때마다 그것을 확정(final) 결과로 굳혀 `results` 에 새 칸으로 쌓습니다
(Chromium `SpeechRecognitionImpl.handleResults`). 가설은 발화 앞부분을 품은 채
자라므로 한 발화가 `"I"`, `"I like"`, `"I like running"` 세 칸이 되고, 이것을 이으면
`I I like I like running` 이 됩니다. 예전에는 이어 붙이는 자리에서 겹치는 단어를
걷어내 막으려 했지만, 인식기가 앞 단어를 고쳐 쓰면(`I goat` → `I go to`) 겹침을
찾지 못해 그대로 쌓였고, 사용자가 실제로 되풀이한 말은 오히려 지웠습니다.

고친 방식은 이렇습니다.

- **`continuous` 는 데스크톱에서만 켭니다.** 휴대폰·태블릿은 끈 채로 받습니다. 표준은
  `continuous` 가 꺼진 세션에 final 을 하나까지만 허용하므로, 가설은 임시(interim)
  결과로 오고 확정 결과는 발화 끝에 한 번만 옵니다. 안드로이드는 켜 두어도 결과를 한
  번 내면 세션을 닫기 때문에 끈다고 잃는 것이 없고, 이어 받기는 원래 하던 대로
  세션이 끝나면 다시 켜는 쪽이 맡습니다. 데스크톱 판단은 녹음과 같은 `isDesktopAgent`
  를 씁니다(리눅스는 데스크톱 사이트를 요청한 안드로이드 태블릿과 가려낼 수 없어
  휴대폰처럼 받습니다).
- 결과는 **순서대로 잇기만** 합니다. 겹친 말을 찾아 지우는 규칙은 모두 뺐습니다. 매
  이벤트마다 그 세션의 `results` 전체를 다시 읽어 덮어쓰므로 같은 결과가 몇 번 와도
  한 번만 남고, 세션이 끝나면 지금까지의 결과를 접어 둔 뒤 새 세션을 뒤에 잇습니다.
- 다시 켤 때 한 박자 쉬어 인식기가 겹쳐 도는 것을 막습니다.
- `no-speech`·`aborted` 는 말을 고르는 동안 흔히 나는 값이라 오류로 알리지 않습니다.
- 마이크를 멈춘 뒤 늦게 도착하는 결과가 손으로 고친 글을 덮어쓰지 않게 막습니다.

잇는 규칙은 `src/lib/transcript.ts`, 인식기를 켜는 쪽은 `src/lib/speech.ts` 에 있고
`tests/transcript.test.cjs`·`tests/speech.test.cjs` 가 휴대폰과 데스크톱이 결과를
보내는 순서를 그대로 재현해 검증합니다.

## 휴대폰에서 아무것도 받아쓰지 못하던 문제

노트북에서는 잘 되는데 휴대폰에서는 **음량 레벨만 오르락내리락하고 답변이 한 글자도
적히지 않던** 문제를 고쳤습니다.

원인은 마이크를 두 곳에서 함께 열었기 때문입니다. 이 화면은 답변을 받을 때
받아쓰기(`SpeechRecognition`)를 먼저 켜고, 음량 레벨과 녹음본을 위해
`getUserMedia` 를 그다음에 엽니다. 노트북 크롬은 둘을 동시에 열어 주지만, 휴대폰
(안드로이드 크롬·iOS 사파리)은 마이크를 한 번에 한 곳에서만 쓰고 **나중에 연 쪽이
마이크를 가져갑니다.** 그래서 늘 녹음이 이기고, 받아쓰기는 조용한 소리만 받다가
발화마다 끊겨 다시 켜지기를 반복했습니다. 음량 막대는 녹음 쪽이 그리므로 멀쩡히
움직여, 겉으로는 녹음은 되는데 인식만 안 되는 것처럼 보였습니다.

받아쓰기와 녹음 중 하나를 골라야 한다면 받아쓰기입니다. 답변 텍스트가 비면 결과
화면의 통계도, AI 피드백도 막히기 때문입니다.

- 휴대폰·태블릿으로 보이는 기기는 처음부터 받아쓰기만 켭니다. 판단은
  `src/lib/micShare.ts` 의 `guessMicMode` 한 곳에 있고, 데스크톱 사파리를 자처하는
  아이패드는 손가락 입력 개수로 가려냅니다.
- UA 만으로는 다 가릴 수 없어, 함께 켠 기기는 **겪어 보고** 정합니다. 사람 목소리
  크기의 입력이 3초 넘게 들어오는데 받아쓰기가 한 글자도 못 내놓으면 녹음을 접고
  받아쓰기를 다시 켭니다. 그 결과는 `yumi-opic:mic-mode` 에 남아 다음부터는 처음부터
  받아쓰기만 켭니다.
- 단, **윈도·크롬OS·맥 노트북은 겪어 보지 않고 늘 함께 켭니다**(`isDesktopAgent`).
  데스크톱 브라우저는 둘을 함께 열어 주므로, 거기서 받아쓰기가 비는 까닭은 녹음이
  아니라 인식 서버 오류·인식기만 있고 받아 적지는 못하는 브라우저·주변 소음입니다.
  예전에는 이것도 충돌로 보고 녹음을 접은 뒤 그 판단을 저장해, 윈도 노트북이 홈에서
  노트북을 권하는 안내를 받고 연습에서도 녹음이 꺼진 채로 남았습니다. 이제는 예전에
  남은 값도 따르지 않습니다. 리눅스는 데스크톱 사이트를 요청한 안드로이드 태블릿과
  UA 가 같아서 겪어 보는 쪽에 남겨 둡니다.
- 받아쓰기가 마이크를 혼자 쓰는 동안에는 입력 레벨을 잴 길이 없습니다. 숫자를
  지어내지 않고 원이 천천히 오르내리며 듣고 있다는 것만 알립니다.
- 잘못 짚었을 수 있으니 답변 상자 아래 **녹음도 함께 켜보기** 로 되돌릴 수 있습니다.
  다시 굶으면 위 규칙이 알아서 한 번 더 접습니다.
- 한 글자도 못 받은 채 인식이 계속 끊겨 재시작 한도에 닿으면 조용히 멈추지 않고
  알립니다. iOS 사파리처럼 버튼을 누른 직후에만 받아쓰기를 켤 수 있는 브라우저에서는
  `다시 녹음하기` 를 누르라고 안내합니다.

기기 판단과 충돌 감지는 브라우저 API 없이 `src/lib/micShare.ts` 에 따로 두어
`tests/micShare.test.cjs` 에서 검증합니다.

## 문제 출처 원칙

`verified`(화면 표시: **기출 복원 기반**)는 공개된 수험자 복원, OPIc 기출 정리 자료, 강의 자료에서 반복 확인되는 문형을 연습하기 좋게 다듬은 것입니다. 공식 OPIc 원문 인증을 의미하지 않습니다.

`adapted`(화면 표시: **출제 유형 기반**)는 해당 주제에서 직접 확인되는 복원이 부족하거나, 비교·이슈·롤플레이형 훈련을 위해 일반적인 OPIc 출제 형식에 맞춰 보완한 문항입니다.

리셋 시 참고한 공개 자료의 예:

- Korea Times / Hackers OPIc 공원·콘서트 공개 연습 문제
- OPIc 관련 공개 기출 정리 블로그의 집, 음악, 공원, 해변, 집휴가 질문 정리
- 공개 수험자 복원 질문 모음의 조깅, 걷기, 쇼핑, 해외여행 문형
- 저장소의 이전 교재 기반 롤플레이 데이터에서 확인한 11 → 12 → 13번 세트 구조

이 저장소는 공식 OPIc 문제은행을 복제하거나 공식 출제 확률을 주장하지 않습니다.

`public/ava.jpg` 는 실제 응시 화면의 면접관 이미지입니다. 화면을 똑같이 만들려고
개인 연습용으로만 넣어 두었습니다.

## 화면 테마

기본 테마는 **라이트**입니다. 다크는 사용자가 직접 고른 경우에만 적용하며, OS의
`prefers-color-scheme` 는 따라가지 않습니다. 홈과 주제별 연습 화면 오른쪽 위 토글로
바꿀 수 있고 선택값은 `yumi-opic:theme` 키로 브라우저에 저장됩니다.

### 토큰 구조

컴포넌트는 원시 색상 대신 의미 토큰만 사용합니다. 팔레트 두 벌은
`src/app/globals.css` 한 곳에 있고, `:root` 가 라이트, `html[data-theme="dark"]`
가 다크입니다. 토큰을 바꾸면 두 테마가 함께 따라옵니다.

| 토큰 | 쓰임 |
| --- | --- |
| `canvas` | 페이지 배경 |
| `surface` / `surface-2` / `surface-3` | 카드 · 안쪽 패널 · 호버 면 |
| `fg` / `fg-muted` / `fg-subtle` | 본문 · 보조 · 흐린 텍스트 |
| `line` / `line-strong` | 장식용 경계 · 입력 컨트롤 경계 |
| `primary` 계열 | 주요 동작, 강조, 포커스 링 |
| `success` / `warn-*` / `danger-*` 계열 | 상태 표시 |
| `exam-*` 계열 | 응시 화면 전용 |

색상은 [ui-ux-pro-max](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill)
스킬의 Language Learning App 팔레트를 기준으로 잡고, 실제 조합마다 대비를 계산해
조정했습니다. 라이트 테마의 본문 텍스트는 4.5:1 이상, 입력 컨트롤 경계는 3:1
이상입니다.

`exam-*` 은 응시 화면만 씁니다. 실제 시험 화면 색(흰 바탕, 주황 버튼, 파란 안내
띠)을 흉내 내야 해서 앱 팔레트와 따로 두었습니다. 다크에서는 흰 바탕이 눈부시므로
배치와 강조색만 남기고 바탕을 어둡게 바꿉니다. 주황은 실제 화면보다 조금 어둡습니다.
흰 글자와 4.5:1 을 지키기 위해서입니다.

새 UI를 붙일 때 `bg-white`, `text-slate-500` 같은 고정 색을 쓰면 다크에서 깨집니다.
위 토큰(`bg-surface`, `text-fg-muted` …)을 사용해 주세요.

## 개발

```bash
npm install
npm test
npm run typecheck
npm run build
npm run dev
```

Node 22 기준으로 CI에서 테스트, 타입체크, 프로덕션 빌드를 실행합니다.

문제 지문을 고쳤다면 `npm run tts` 로 그 문항의 낭독 mp3 도 다시 만듭니다.

## 화면 문구 용어

UI 문구는 오픽 수험 커뮤니티와 다른 모의고사 서비스에서 쓰는 표준 용어를 따릅니다.

| 개념 | 이 앱의 표기 |
| --- | --- |
| Background Survey | 배경 설문 주제 |
| 전체 15문항 연습 | 실전 모의고사 |
| 한 주제 반복 연습 | 주제별 연습 |
| 단문 연습 | 1문제 연습 |
| Description | 묘사 |
| Routine / Habit | 습관 |
| Experience | 경험 |
| Role Play 11 / 12 / 13 | 질문하기 / 문제 해결 / 관련 경험 |
| Comparison | 비교 |
| Advanced issue | 이슈 |

유형 이름은 `src/lib/exam.ts` 의 `TYPE_LABELS` 와 `EXAM_GROUPS` 한 곳에서만
관리합니다. 새 화면을 붙일 때 문구를 따로 적지 말고 이 값을 가져다 쓰세요.
